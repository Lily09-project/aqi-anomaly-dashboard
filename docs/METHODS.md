# 方法說明與模型卡

本文件說明 Taiwan Air Lab 的資料契約、分析方法與限制。演算法位於 `src/analytics/`，資料匯出入口為 `src/export_web.py`。目前畫面與指標以同一份部署產物為準，不將測試資料的成績當成正式模型資料的表現。

## 資料與執行模式

| 用途 | 資料與契約 |
| --- | --- |
| 正式網站 | `python run_all.py --mode api --require-api`：免註冊 Open-Meteo Air Quality API 的 CAMS Global 模型估算；風場來自 Open-Meteo Forecast API |
| 地點與解析度 | 四個臺灣查詢錨點對應 API 回傳的實際模型格點；CAMS Global 約 45 公里、原生每 3 小時，API 逐時輸出含插值，不是地面測站或新增實測 |
| 正式 AQI 與單位 | 使用 API 提供的美國 EPA AQI；PM、臭氧與 CO 依來源濃度契約使用 μg/m³，風速為 m/s，時區為 Asia/Taipei |
| 測試與 PR 預覽 | `--mode sample` 使用固定種子、固定日期的八站合成 fixture，供重現與已知答案驗證；不作正式網站的來源替代 |
| 來源失敗 | 正式 require-api 模式停止建置，不讀舊 CSV 或回退 sample 發布；非正式本機模式的回退必須明示 Sample Data |

測試 fixture 的 AQI 由 `aqi_scale.py` 以污染物分段換算，臭氧輸入為 ppb，並以逐時濃度簡化官方移動平均。這條測試資料路徑與 CAMS 正式 AQI 的標準和單位不同，不能混用。

來源驗證、時間範圍、輸入 SHA-256、模型格點與使用條款見[資料契約](data-contract.md)。正式資料須通過至少 30 天歷史、四個獨立格點、時間對齊與 freshness 等檢查。Open-Meteo 免費 API 限非商業用途；來源歸屬 Open-Meteo 與 CAMS，詳見[官方使用條款](https://open-meteo.com/en/terms)。

## 前處理與時間邊界

`build_panels(..., causal=True)` 將資料對齊為「時間 × 地點」逐時面板，僅以前一筆有效值向前填補最多 3 小時，不借用未來端點；較長缺口中超過此上限的部分仍缺值。正式分析匯出使用這條因果路徑。

另保留 `causal=False` 的描述性短缺口內插工具：只填補總長不超過 3 小時的內部缺口，長缺口整段保留缺值。它不是預測評估的前處理方式。各分析對不可用特徵另行處理，缺值不等於零。

## 機率預報

- 每個時距 h = 1…24 各擬合一個 ridge 迴歸，α = 1，避免遞迴預測誤差累積；標準化參數只由訓練樣本計算。
- 特徵包括目前 AQI、1／3 小時前 AQI、過去 6 小時平均、PM2.5、風速，以及目前與目標時刻的氣候值。氣候值是訓練期間各地點、各小時的平均值。
- 時間順序切成訓練 70%、校準 15%、測試 15%。訓練及校準樣本的目標時間也須落在各自截止時間內。
- 預測使用的上游關係僅由訓練區間 PM2.5 選擇，新增上游相對氣候值的異常特徵；不使用完整歷史傳播圖選擇上游後再宣稱樣本外獨立評估。
- 校準期殘差的 10%、50%、90% 分位數形成 P10／P50／P90，測試期評估實際涵蓋率與 MAE。名目 80% 區間不保證在相依或漂移資料上達到 80%。
- 與持續性及訓練期氣候值基準使用相同測試樣本比較。最新預報從資料末端向後延伸 24 小時；它不是官方氣象或空品預報。

結果查閱當次匯出的 `model.json`：含切分時間、各時距 MAE、涵蓋率、樣本數、基準與上游特徵比較。任何成績都須連同同一份 `provenance.json` 的來源、資料範圍與輸入 SHA-256 解讀；不沿用舊 fixture 的固定成績。

## 出門時段規劃

Python 的 `planner.py` 與瀏覽器實作以 parity 案例比對：

1. 由 P10、P50、P90 建立分段線性 CDF，區間外以最近一段斜率外推並截於 [0, 1]。
2. 計算每小時 AQI 超過門檻的估計機率；敏感族群門檻 100、一般門檻 150。
3. 在可用的連續預報時段中選擇平均超標機率最低的 N 小時；同分依中位數較低、較早順序決定。
4. 瀏覽器依當前時間排除已過期預報，不能跨越缺時拼成連續時段；有效資料不足時顯示無結果。

這是依模型分位數得到的近似排序工具，不是個人暴露量或健康風險保證。

## 回顧性傳播分析

- 對 PM2.5 扣除各地點、各小時的平均值後標準化，檢查地點間 ±12 小時互相關。
- 每對地點選最高有效相關的落後值；相關至少 0.3、最佳落後非零才建立方向關係。相同相關優先較短絕對落後。
- 每個下游地點選延遲最短的上游，同延遲選相關較高者。
- 展示圖可使用完整資料期間作歷史描述；預報的上游關係另由訓練期間選擇。
- 共用日夜變化、共同模型輸入及空間平滑仍可能造成相關；箭頭不證明污染實際傳播或因果。

`propagation.json` 記錄當次結果；只有合成 fixture 才有注入延遲的已知答案，不替正式 CAMS 資料捏造 truth。

## 回顧性異常與相似事件

- 每個地點、每個小時以中位數和 MAD × 1.4826 計算穩健 z 分數；PM2.5 z ≥ 4.5 的時段合併為事件，容許中間缺一小時。
- 高峰前後窗口內，若至少兩個其他地點也有異常高峰，標為區域事件；窗口由當次最長傳播延遲決定，無關係時使用預設值。
- 高峰各因子的 z 分數依絕對值排序作相關性解釋；以同一組因子向量的歐氏距離找相似事件，排除自己。
- 基線、區域標記與相似事件使用完整歷史作回顧分析，不是即時可交易／可預警的因果偵測器。相似事件可出現在事件前或後。

`anomalies.json` 的已知答案驗證僅對合成 fixture 提供；不能把合成事件的召回率當真實污染事件的召回率。

## 情境模擬

`whatif.py` 用目前 AQI、PM2.5、PM10、臭氧、風速與時刻 sin／cos 擬合下一小時 AQI 的 ridge 模型。

- 訓練、校準依時間切開；標準化與滑桿範圍／預設值只由訓練資料計算。
- 滑桿範圍採訓練資料 1%–99% 分位數；時刻為 0–23 時。
- 臭氧單位由來源契約傳入：正式 CAMS 為 μg/m³，測試 fixture 為 ppb。僅改標籤不轉換原數值，未知單位拒絕匯出。
- 匯出標準化參數、係數、截距及校準殘差；12 組 parity 案例檢查 Python 與 TypeScript 推論一致。
- `web/src/lib/fixtures/whatif.json` 是測試契約，不是正式部署資料；變更模型或匯出時須重建並通過一致性測試。

滑桿顯示條件相關，不表示改變某項污染物就會使大氣 AQI 依此變化，也不保證超出訓練分布後仍準確。

## 模型監控與驗證

- 覆蓋率低於名目 80% 達 5 個百分點標為太窄，高於 10 個百分點標為偏寬。
- 上游特徵的增益以同一測試期、下游地點的有／無上游模型比較；不預設每個時距都改善。
- 漂移比較最近 7 天與之前 14 天平均 PM2.5，差異以參考期標準差衡量；絕對偏移 ≥ 0.5 為留意、≥ 1 為警示，資訊不足另標示。
- `test_causal_training_contract.py` 驗證改變未來資料不改訓練前處理、上游、模型參數，並驗臭氧單位與數值 parity。
- 單元、已知答案 fixture、來源契約、真實 API 與正式資料 browser acceptance 分開驗證。fixture 成功不代表 API 可用或正式模型表現相同。

## 使用限制

這是可追溯的模型資料分析展示，不是環境部測站實測、官方預報、即時警報或健康建議。時間相依、缺值、模型誤差、空間平滑與分布改變都會影響評估。資料過期、來源失敗或有效預報不足時應明確顯示限制，不能用合成數據充作完成。
