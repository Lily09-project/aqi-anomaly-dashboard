# Taiwan Air Lab — 驗收規格

本文件在重做開始前訂定，是判斷專案「完成」的唯一標準。每一條驗收項目都對應到可自動執行的測試，
最終 PR 必須逐條附上證據（測試名稱或 CI job），全部通過才算完成。

## 0. 範圍與架構決策

| 項目 | 決策 |
| --- | --- |
| 資料 | 預設使用可重現的合成資料（固定基準日期與種子），模擬 8 個測站、至少 60 天逐時觀測，並刻意注入「跨測站傳播」與「污染事件」等可驗證的結構；保留環境部 API adapter，但展示站不依賴它 |
| 分析核心 | Python（`src/`），新增 `src/analytics/` 模組，全部可離線、可重現 |
| 前端 | 全新 React + TypeScript + Vite 靜態網站（`web/`），部署於 GitHub Pages |
| 舊版 Streamlit | 移除，由新網站與新測試取代 |
| 誠實標示 | 全站明確標示「模擬資料」，不是即時監測、正式預報或健康建議 |

## 1. 功能驗收（創新功能）

### F1 測站總覽地圖
- 以測站經緯度繪製台灣示意地圖，顏色依 AQI 等級，點選測站進入詳情。
- 依環境部 AQI 分級顯示目前等級與族群建議。
- 驗收：AQI 分級邊界單元測試；E2E 點選測站後網址與詳情頁同步。

### F2 機率預報與「最佳出門時段」規劃
- 每個測站未來 24 小時的分位數預報（P10／P50／P90），使用分位數迴歸並以滾動回測校準。
- 使用者選擇族群敏感度與活動時長，系統推薦風險最低的時段並解釋原因。
- 驗收（單元測試）：
  - 每個時點 P10 ≤ P50 ≤ P90；
  - 推薦時段是所有候選時段中風險分數最低者；
  - 活動時長超過可用範圍時回傳明確的無結果狀態。

### F3 污染傳播追蹤
- 計算測站兩兩之間 PM2.5 的領先／落後互相關，找出「上游預警」關係，以網路圖呈現。
- 提供事件重播動畫，可暫停與逐步播放，並遵守 `prefers-reduced-motion`。
- 驗收：
  - 合成資料中注入的已知傳播延遲（例如 3 小時），偵測結果誤差在 ±1 小時內；
  - 無傳播關係的測站對不被標示為顯著。

### F4 異常歸因與相似事件
- 每個異常事件列出各污染物／氣象因子相對基線的 z 分數排名，作為「為什麼異常」的解釋。
- 以特徵向量找出歷史上最相似的 3 個事件。
- 驗收：
  - 歸因排序與 z 分數絕對值一致；
  - 相似事件排除自己且依距離排序；
  - 合成資料中注入的事件能被偵測到（召回率 ≥ 80%）。

### F5 情境模擬（瀏覽器端模型）
- 匯出可解釋的線性模型係數，使用者用滑桿調整風速、前一時段 PM2.5 等條件，即時看到預測值與區間。
- 驗收：同一組輸入，TypeScript 推論結果與 Python 預測誤差 < 1e-6（跨語言一致性測試）。

### F6 模型監控
- 預測區間覆蓋率校準圖、與持續性基準模型的 MAE 比較、分布漂移指標。
- 驗收：覆蓋率計算單元測試；模型 MAE 優於持續性基準（回測證明，否則誠實顯示「未優於基準」）。

### F7 資料可信度
- 資料來源、產生時間、種子、SHA-256、方法限制。
- 驗收：E2E 顯示的資料雜湊與 manifest 一致。
